# 0011. ORM for Postgres: Prisma vs Drizzle

## Status
Accepted (2026-09-24) — **B. Drizzle** (SPEC §15 item 1)

## Context
`packages/db` needs an ORM or query builder for migrations and typed queries behind the **mandatory scoped repository** (ADR-0016). The design leans on Postgres features:
- `INSERT … ON CONFLICT DO NOTHING RETURNING` (webhook idempotency);
- `SELECT … FOR UPDATE` and `FOR UPDATE SKIP LOCKED` (withdrawal-erasure batching);
- advisory locks (token refresh);
- partial unique indexes on jsonb expressions;
- `NULLS NOT DISTINCT` (`store_delivery_rates`);
- possibly RLS later.

Better Auth (ADR-0012) needs an adapter, and supports Drizzle, Prisma and Kysely ([Better Auth database](https://www.better-auth.com/docs/concepts/database)).

## Options
**A. Prisma**
- Mature schema-first migrations and a large community; the Shopify app template's default.
- Postgres-specific features above need raw SQL (`$queryRaw`), which weakens "no raw SQL outside `packages/db`" (it would be allowed, but more of it). Heavier runtime and generated client.

**B. Drizzle**
- SQL-shaped TypeScript query builder; schemas in TypeScript; `drizzle-kit` migrations. First-class `onConflictDoNothing`, `for('update', { skipLocked })`, and partial indexes via `sql` expressions. Thin runtime.
- Younger ecosystem; migrations are less opinionated, so the team must review generated SQL.

**C. Kysely** (query builder only)
- Very close to SQL, excellent types, and Better Auth's built-in adapter.
- No schema/migration tooling beyond basic migrations; more hand-written DDL.

## Recommendation
**B. Drizzle.** The data layer is deliberately SQL-heavy and Postgres-specific, and Drizzle expresses those features without raw SQL escape hatches. Its TypeScript schemas make the scoped repository wrappers straightforward, and Better Auth's Drizzle adapter can generate the identity tables into the same schema.

## Decision
**Drizzle** (`drizzle-orm` + `drizzle-kit`) for all Postgres access in `packages/db`. **Better Auth's Drizzle adapter shares the same Drizzle schema and migration history.** The identity tables are generated by the Better Auth CLI into the Drizzle schema and committed, so there is one migration stream (`pnpm db:migrate`), not two.

## Consequences
- `packages/db` holds Drizzle schemas and migrations for all SPEC §6.1 tables, including the Better Auth tables (generated, then committed).
- The lint rule restricts `drizzle-orm` imports to `packages/db` and `packages/auth` (ADR-0016).
- The Shopify embedded app uses a custom session storage over `integrations` (shopify-integration §4.1), not the template's Prisma session store.
